# Design decisions

## Infrastructure
| # | Decision |
|---|----------|
| 1 | Two stacks, one per region, each with its own `main.tf` and state. Each spans four subscriptions through provider aliases. |
| 2 | **All deployment values live in `terraform.tfvars`.** Code contains only Azure-mandated constants (documented inline). Tenant and subscription IDs are the exception (decision 17). |
| 3 | No management group code. Azure Policy is assigned at **subscription scope**, per subscription, from the primary stack only (policy is not regional). Definitions are built-in policies looked up by display name. |
| 3a | Mandatory tags: `mandatory_tag_names` + `tags` in tfvars; validated at plan, required by every module, enforced by policy (require on resource groups, inherit from resource group). Policies are rolled out in audit mode before enforcement. |
| 4 | Hub-and-spoke (not Virtual WAN). Azure Firewall **Standard**, one policy per region. Identity and workload VNets are spokes. |
| 5 | Private DNS zones exist once, in the primary hub network resource group. The secondary only links its hub VNet to them (`create_zones` in tfvars). |
| 6 | DNS path: spoke VMs -> firewall DNS proxy -> DNS Private Resolver inbound -> AD domain forwarded to the domain controllers. |
| 7 | Identity: domain controllers with private IPs only; count, size, image and placement (availability set or zones) are set in tfvars. Default: two DCs per region in an availability set, with an optional third DC in Central India. |
| 8 | AD DS promotion is manual. Terraform builds the VMs only. |
| 9 | DC admin password: generated by Terraform and stored in a Key Vault in the identity subscription (RBAC, purge protection, private endpoint). It is also present in Terraform state and in plan files, which is why plan artifacts are encrypted. |
| 10 | Workload subscription: resource group, VNet, NSGs, route table, Recovery Services Vault. No VMs, SQL or storage. |
| 11 | DCs are not backed up. DR = native AD replication to the other region. Enable AD Recycle Bin after promotion. |
| 12 | Log Analytics workspace per region in the governance subscription; retention is set in tfvars. |
| 13 | Remote state: GZRS storage account in the governance subscription, Entra ID authentication only, created by `scripts/Bootstrap-TerraformBackend.ps1`. |
| 14 | Spoke route tables and DNS servers reference the firewall IP (first free address of AzureFirewallSubnet) from tfvars; a `check` block warns if Azure assigns a different one. |

## Delivery (CI/CD)
| # | Decision |
|---|----------|
| 15 | GitHub Actions with two workflows: **Terraform Plan** (pull requests, `main`, manual) and **Terraform Apply** (started by `workflow_run` when a plan on `main` finishes). Planning and applying are separate concerns. |
| 16 | Apply uses the **saved, reviewed plan** (`terraform apply tfplan`), never `-auto-approve`. Plans without changes skip the approval. The plan artifact is encrypted and kept for 5 days. |
| 17 | Tenant and subscription IDs are kept out of Git: `ids.auto.tfvars` (git-ignored) locally, repository variables passed as `TF_VAR_*` in CI. An `ids.auto.tfvars.example` documents the format. |
| 18 | Changes reach `main` only through pull requests: a ruleset requires the plan status check, an up-to-date branch and squash merging, and blocks force pushes. |
| 19 | Production deployments require approval on the `prod` environment, which only `main` may deploy to. |
| 20 | The pipeline authenticates with a service principal client secret (Contributor, User Access Administrator, Resource Policy Contributor). OIDC with separate plan and apply identities is the planned replacement. |
| 21 | Key Vault allows public network access, protected by RBAC, because GitHub-hosted runners have no fixed IP. Network restrictions are configured in tfvars once Terraform runs inside the VNet. |
| 22 | Terraform version and provider versions are pinned (`TF_VERSION` variable, committed `.terraform.lock.hcl`) because a saved plan only applies with identical versions. |

## Open items
* The secondary stack is not yet deployed by the pipeline.
* Policy: only built-in definitions are used. Tag *values* are not validated (only presence).
* Verify VM size availability and Windows Server image compatibility in both regions before changing them.
* Firewall rules cover Active Directory and internal ICMP only. Internet egress (for example Windows Update) needs application rules.
* Log Analytics long-term archive, VM guest monitoring (Azure Monitor Agent), Defender for Cloud and RBAC design are not covered.
